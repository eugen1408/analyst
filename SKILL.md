# Анализ программного проекта

Анализ выполняют два самостоятельных скилла в `.agents/skills/`:

- [Бизнес-аналитик](.agents/skills/business-analyst/SKILL.md) — цели, роли, бизнес-правила, пользовательские сценарии; результат `business-analysis.md`.
- [Системный аналитик](.agents/skills/system-analyst/SKILL.md) — архитектура, данные, интеграции, безопасность и покрытие бизнес-требований; результат `system-analysis.md`.

Перед началом анализа предложи пользователю выбрать режим:

1. **Бизнес-аналитик** — цели, роли, бизнес-правила и пользовательские сценарии; результат `business-analysis.md`.
2. **Системный аналитик** — архитектура, данные, интеграции и безопасность; результат `system-analysis.md`.
3. **1 + 2 — оба** — бизнес-анализ, затем системное проектирование; результат — оба документа.

Попроси ответить `1`, `2` или `1 + 2` (также принимай `3` как выбор обоих). Дождись выбора и не определяй режим самостоятельно. Если пользователь уже явно выбрал режим в текущем запросе или ранее в разговоре, используй этот выбор без повторного вопроса.

Для `1` прочитай инструкции бизнес-аналитика, для `2` — системного аналитика, для `1 + 2` — оба скилла: сначала согласуйте бизнес-поведение, затем системное решение. Общий `questions.md` сохраняет номера, приоритеты, ответы и допущения обеих ролей.

Сохраняй общий процесс: plan mode (либо явный план, если режим недоступен), сбор информации → черновик в чате без записи файлов → уточнение → подтверждение, проверка полноты и запись финальных файлов. При совместной работе показывай оба черновика и проверяй полное покрытие бизнес-анализа системным, отсутствие противоречий и открытых блокирующих вопросов. Уже согласованные ответы и подтверждения используй повторно без повторного опроса.

Для запроса одной роли второй документ не требуется. Если по ходу работы потребуется подключить вторую роль, предложи изменить режим и дождись выбора пользователя.

## Спецификация и реализация

Для подготовки спецификации или реализации используй [sdd](.agents/skills/sdd/SKILL.md) как следующий этап после требуемого анализа. Передавай имеющийся текст задачи, согласованную аналитику и `questions.md`; если требования уже достаточны, не запускай повторный сбор. SDD доступен и напрямую — без предварительного вызова analyst. Выбор `1 / 2 / 1 + 2` относится к аналитике, а не к разрешению писать код. Для реализации нужна явная команда пользователя; уже полученную команду учитывай без повторного запроса.

Любые схемы в аналитике и спецификации оформляй только Markdown-блоками `mermaid`; текстовые шаги и таблицы не заменяй схемами без необходимости.
