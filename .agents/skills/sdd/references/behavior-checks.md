# Проверка поведения скиллов

Используй эти случаи при изменении инструкций и шаблонов. Выполняй прогоны
в отдельной временной папке, с одними и теми же входными материалами и доступными
инструментами. Для сравнения фиксируй версию скилла, шаблона и модели, если она
известна. Прогоны LLM оценивай по наблюдаемым результатам и соблюдению границ,
а не по буквальному совпадению текста. Таблица не является доказательством
прохождения: записывай, какие прогоны действительно выполнены и что обнаружено.

| Случай | Вход | Проверяемое поведение |
| --- | --- | --- |
| Выбор роли | «Подготовь аналитику для записи на приём», режим не выбран | Предложены 1 / 2 / 1 + 2; предметный анализ не начинается до выбора |
| Самостоятельная роль | Выбран 1; описаны клиент, администратор и отмена записи | Бизнес-анализ покрывает обе роли и отмену; нет технических контрактов и автоматически созданного системного документа |
| Достаточные входы | Есть задача, согласованные оба документа и вопросы; запрос только на спецификацию | Использованы готовые материалы и ID; нет повторного опроса решённого и реализации кода |
| Недостаток данных | «Создай спецификацию» без описания задачи | Запрошена цель и ожидаемое изменение; предметная задача, номера и API не выдуманы |
| Конфликт | Бизнес-анализ разрешает отмену после подтверждения, системный запрещает; пользователь не выбрал правило | Конфликт показан и оформлен вопросом; зависимая часть не финализирована и не реализована |
| Неполный контракт | Задана интеграция отправки уведомления, но неизвестны поля и повторы | Назначение и поток описаны; неизвестные контракты и политика повторов вынесены в Q-NN; нет выдуманных endpoint-ов |
| Изменение согласованного | После согласования изменено правило отмены | Сохранены ID; отмечены и обновлены затронутые критерии, состояния и решения; изменённое поведение согласовано |
| Схемы | Запрошены процесс, состояния, взаимодействия и модель данных | Схемы только в mermaid, соответствуют тексту; бизнес-документ остаётся на уровне бизнеса |
| Блокирующий вопрос | Есть явная команда реализовать, но открыто правило расчёта суммы | Исследование продолжается, зависимый код не пишется, блокер не снимается молчанием или временным допущением |
| Реализация разрешена | Исходный запрос «реализуй», есть достаточные требования и принятые решения | После проверки спека работа продолжается без повторного запроса той же команды |
| Декомпозиция | Согласован эпик из двух зависимых частей | Есть обзор, дочерние спеки, реальные зависимости и единый источник вопросов; папка архивируется целиком после сквозной проверки |
| Провал проверки | Код написан, но обязательный тест падает | Спецификация не объявлена реализованной и не архивирована; результат проверки сообщён фактически |

При повторных прогонах сравнивай: сохранение требований и ID, число непокрытых
критериев, число решений без основания, корректность остановок и результаты
формального валидатора. Если найден сбой, исправляй его причину и повторяй
соответствующий случай. Не расширяй инструкции универсальным правилом по одному
частному примеру, пока не проверена его применимость.
