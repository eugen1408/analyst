# Контракт результата системного анализа

Основной документ — `system-analysis.md`; вопросы — `questions.md`. Входные UC, BR, AC и ограничения должны иметь системное покрытие, включая данные, интеграции, безопасность и применимые NFR.

## Общие правила результата

1. **Контекст входа.** Зафиксируй использованные материалы и их версии/даты, если известны. Отдельно обозначь согласованные факты, решения, предложения и допущения. При конфликте покажи обе версии и запроси выбор; не решай его незаметно по дате или удобству.
2. **Контракт выхода.** Используй обязательные разделы выбранного шаблона и стабильный порядок. Неприменимый раздел помечай «Не применимо» с причиной; неизвестный — ссылкой на Q-NN. Пустота не означает отсутствие требований. Неизвестное блокирующее нельзя объявлять согласованным.
3. **Устойчивые идентификаторы.** UC, BR, AC, NFR и Q-NN сохраняются при уточнениях; новые получают следующий свободный номер. Для декомпозиции нумерация уникальна в пределах задачи. Не меняй имена, порядок и решения без нового основания.
4. **Атомарность и проверяемость.** Одно правило — одно требование; один критерий — наблюдаемый результат в конкретных условиях. Вместо «быстро», «корректно», «удобно» используй проверяемое поведение либо вопрос о метрике. Значения ограничений не выдумывай.
5. **Основание и покрытие.** Каждое существенное требование имеет источник или согласованный ответ; каждое решение — требование или согласованное основание. Матрица покрытия включает критерии, альтернативы, ошибки и отмены. Число покрытых пунктов считай по реальным ID; не объявляй 100% на основании одного happy path.
6. **Проверка в два прохода.** Сначала проверь структуру, ID, ссылки, шаблонные заглушки и формат схем. Затем отдельно прочитай документ как заказчик/разработчик: ищи противоречия, пропущенные роли, условия, состояния, ошибки и решения без основания. Успех формального валидатора не доказывает содержательную полноту.
7. **Изменение требований.** При новом ответе отметь затронутые ID и обнови связанные разделы и документы. Прежнее согласование не распространяется на изменённое поведение; неизменённые решения повторно не согласовывай. При обновлении не переписывай весь документ ради стиля.
8. **Условия готовности.** Нет открытых блокирующих вопросов; обязательное содержание заполнено или обоснованно неприменимо; все существенные требования покрыты; временные допущения видны; проверки описаны фактически. Если условие не выполнено, явно укажи пробел, а не завершай молча.
9. **Формат схем.** Все схемы — только fenced-блоки `mermaid`; узлы и переходы соответствуют тексту и одним и тем же терминам. Если доступен Mermaid-рендерер, проверь синтаксис им. Если нет, проверь структуру вручную и не утверждай, что схема отрендерена. Текстовые шаги и таблицы остаются допустимыми.

Это повышает воспроизводимость структуры и решений, но не гарантирует идентичность формулировок при повторном запуске LLM.

## Формальная проверка сохранённых документов

При использовании встроенного шаблона можно выполнить [валидатор](../../sdd/scripts/validate_document.py):

```bash
python3 <путь-к-sdd>/scripts/validate_document.py <документ.md> --kind system --stage draft
python3 <путь-к-sdd>/scripts/validate_document.py <документ.md> --kind system --stage final
```

Для эпика используй `--kind epic`, для журнала вопросов — `--kind questions`.
Валидатор проверяет разделы встроенного шаблона, выбранный статус документа, повторные определения ID,
незакрытые code fences, формат блоков схем, оставшиеся заглушки и открытые
блокирующие вопросы внутри документа. Внешний `questions.md` проверь отдельным
запуском. Код 0 — формальных ошибок нет; код 1 — ошибки; код 2 — ошибка входа.
Результат — JSON с ошибками и предупреждениями в устойчивом порядке.
Он не проверяет смысл, полное покрытие, реальные контракты или синтаксис Mermaid. Типовые заглушки обнаруживаются по форме; скрытые пропуски требуют содержательной проверки.
Если используется иной шаблон проекта или валидатор недоступен, выполни
эквивалентную структурную проверку по этому шаблону; не переделывай документ
под встроенный шаблон только ради прохождения скрипта.
